## Explanation

A single Bitcoin Core node can load multiple independent wallets at once (`miner`, `receiver`, `alice` here). Each wallet keeps its own private keys, its own addresses, and its own balance — they're separate files on disk, not separate accounts inside one file.

Because one node can host several wallets, most wallet RPCs (`getnewaddress`, `getbalances`, `sendtoaddress`, `getaddressinfo`, ...) need to know *which* wallet to act on. That's what `-rpcwallet=<name>` does — it's a flag on the RPC call itself, not a login: it tells `bitcoin-cli` "run this next command against wallet X." Without it, the node either uses a default wallet or errors out if there's more than one wallet loaded and none specified.

That's why `getaddressinfo` on `bcrt1qx208aa...` returns `"ismine": true` when called with `-rpcwallet=receiver` — that address was generated by the `receiver` wallet, so only *that* wallet's context recognizes it as its own. Calling the same RPC with `-rpcwallet=miner` or `-rpcwallet=alice` on the same address would report `"ismine": false`, since those wallets never generated it and don't hold its private key.
